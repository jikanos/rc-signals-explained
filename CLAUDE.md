# rc-signals-explained

Обучающая презентация (Reveal.js + Vite) про сигналы управления в RC/FPV:
эволюция протоколов управления моторами (PWM → Oneshot125 → Multishot → DShot)
и протоколы связи (PPM, SBUS, CRSF). Слайды — интерактивные SVG-схемы со
слайдерами (ширина импульса, throttle, каналы), которые пересчитывают графику
в реальном времени; каждая тема начинается с текстового intro, объясняющего,
какую проблему предыдущего протокола она решает ("← От X" / "→ Дальше").

## Стек

- Vite (сборка/dev-сервер)
- reveal.js (движок презентации, тема `black`)
- Никакого фреймворка — слайды это чистый HTML/SVG/JS

## Структура

Каждый слайд — отдельная пара файлов в `src/slides/`, с числовым префиксом
для порядка показа:

- `NN-name.html` — разметка `<section>...</section>` для этого слайда
- `NN-name.js` — только для интерактивных слайдов: `export function initXxxSlide()`
  с логикой рендера/слушателями (титульные слайды-разделители — только `.html`,
  без `.js`)

Если у темы несколько слайдов (вертикальный стек, см. ниже), они лежат в
своей подпапке `NN-topic/` вместо плоских файлов с длинным именем —
например `03-pwm/intro.html`, `03-pwm/demo.html`, `03-pwm/demo.js`.

`src/main.js` импортирует HTML-файлы через Vite `?raw`, склеивает их в
`.slides` контейнер и вызывает init-функции — в этом файле порядок слайдов
и задаётся (просто меняй порядок импортов/элементов массива `slides`).

Элемент массива `slides` — либо строка (обычный горизонтальный слайд), либо
массив строк (вертикальный стек: несколько слайдов друг под другом на одну
тему, `renderSlide()` в `main.js` оборачивает их в общий внешний `<section>`,
как того требует reveal.js для вертикальной навигации). Пример — PWM:
`[pwmIntroSlide, pwmDemoSlide]` — текстовое объяснение сверху, анимация снизу.

Текущий порядок (протокольные темы — вертикальные стеки, обычно
`intro` + `demo`, иногда с доп. подслайдами вроде `calibration`/
`telemetry`/`crc`; титульные/сводные слайды — обычные горизонтальные строки):
`01-title` → `02-motor-protocols-title` → `03-pwm/` (intro, demo, calibration)
→ `04-oneshot125/` → `05-multishot/` → `06-dshot/` (intro, demo, telemetry, crc)
→ `07-motor-chronology` (таблица-сводка цепочки PWM→DShot) → `08-uavcan/`
(боковая ветка — шина вместо провода на каждый ESC, не часть цепочки
"решает боль предыдущего", идёт ПОСЛЕ таблицы-сводки, а не внутри цепочки)
→ `09-comm-protocols-title` → `10-ppm/` → `11-sbus/` → `12-crsf/` →
`13-comm-chronology` (таблица-сводка) → `14-thanks` (QR-код на саму
презентацию).

Не каждый протокол — следующий шаг эволюции. UAVCAN намеренно оформлен как
"другая ветка" (нейтрально-серый акцент вместо цепочки "← От / → Дальше"),
а не как продолжение цепочки PWM→...→DShot — так и объясняется читателю
прямо на слайде. Презентация сознательно ограничена протоколами "по
кабелю" между конкретными узлами дрона (TX→RX, RX→FC, FC→ESC) — радиолинк-
протоколы (XJT, ExpressLRS и т.п.) и телеметрия верхнего уровня без
своего провода (MAVLink, между FC и GCS/компаньон-компьютером) не входят
в объём.

Слайды, объясняющие сквозные концепции (калибровка ESC, DShot-телеметрия,
CRC), лежат подслайдом внутри темы, где впервые появляются, но получают
`id` на `<section>` (например `id="esc-calibration"`) — из любого места
презентации на них можно сослаться через `<a href="#/esc-calibration">`,
это штатный способ внутренней навигации в reveal.js. Проверяй `grep`-ом
по `src/slides/`, что все упоминания темы (не только в теме её "дома")
ссылаются на такой слайд.

Чтобы добавить новый слайд: создать `NN-name.html` (+ `.js` если нужна
интерактивность) в `src/slides/`, импортировать в `main.js` и вставить в
нужное место массива `slides` (и вызвать init, если есть) — оберни в `[...]`,
если это должен быть вертикальный подслайд к соседнему.

`index.html` — только пустой каркас (`<div class="reveal"><div class="slides">`),
слайды в него не пишутся напрямую.

- `src/style.css`, `src/assets/` — не используются активно (шаблонные остатки
  от `npm create vite`)
- `vite.config.js` — `base: '/rc-signals-explained/'` (обязателен для GitHub
  Pages, т.к. сайт живёт в подпути, а не в корне домена)
- `.github/workflows/deploy.yml` — автодеплой на GitHub Pages при пуше в `main`

## Команды

```
npm run dev       # локальный сервер (обычно http://localhost:5173/)
npm run build     # сборка в dist/
npm run preview   # предпросмотр собранного dist/
```

## Деплой

Пуш в `main` → GitHub Actions билдит и публикует `dist/` на GitHub Pages.
Источник Pages в настройках репозитория должен быть выставлен на
**GitHub Actions** (Settings → Pages → Source).

Сайт: https://jikanos.github.io/rc-signals-explained/

## Стиль кода

Слайды оформлены с явными закрывающими тегами SVG (`</line>`, `</path>` и
т.п. вместо самозакрывающихся `/>`) и многострочными атрибутами `style` —
сохраняй этот стиль при добавлении новых слайдов.
